## ⚠️ Venv portability gotcha (Windows)

If you copied the `venv/` folder from another machine, the `.exe` launcher shims (`uvicorn.exe`, `pip.exe`, etc.) have the **source machine's Python path hardcoded**, so they fail with `Fatal error in launcher: Unable to create process using ...`.

**Quick workaround:** call modules via `python -m`:
```
python -m uvicorn app.main:app ...
python -m pip install ...
```

**Permanent fix:** recreate the venv on this machine. The `python.exe` inside the venv works fine — only the .exe shims are broken.

```powershell
Rename-Item venv venv_old
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
python -m pip install -r requirements.txt
python -m pip install httpx reportlab pypdf
Remove-Item -Recurse -Force venv_old
```

## Transferring to Another Machine

### Option A: ZIP and Transfer (simplest)

```bash
# On source machine — exclude large/generated files
# Windows PowerShell:
Compress-Archive -Path Capstone -DestinationPath Capstone.zip -CompressionLevel Optimal

# On target machine:
Expand-Archive Capstone.zip -DestinationPath .
cd Capstone

# Delete the old venv (it's not portable) and recreate
rmdir /s /q venv          # Windows
rm -rf venv               # Linux
python -m venv venv
```

**What TO include in the zip:**
- All `.py` files (scripts/, app/, gradio_ui/)
- `configs/` folder
- `requirements.txt`
- `db_schema.sql`
- `expert_ui/` folder
- `SETUP.md` (this file)
- `GAPs v2/` dataset folder (if transferring data too)
- `RDD/` dataset folder (if transferring data too)

**What to EXCLUDE (save space):**
- `venv/` — not portable, recreate on target
- `outputs/` — training checkpoints (large, regenerated)
- `data/images/` — regenerated by script 01
- `data/*.json` — regenerated by script 02
- `eval_results/` — regenerated by eval scripts
- `__pycache__/` — Python bytecode cache
- `.npy` files if already converted

### Option B: Git (recommended for code, not data)

```bash
# Initialize if not already
git init
echo "venv/" >> .gitignore
echo "outputs/" >> .gitignore
echo "data/images/" >> .gitignore
echo "__pycache__/" >> .gitignore
echo "*.npy" >> .gitignore

git add -A
git commit -m "Initial commit"
git remote add origin <your-repo-url>
git push -u origin main

# On target machine:
git clone <your-repo-url>
cd Capstone
# Then follow Quick Start from step 2
```


### Phase 4: Fine-Tuning (on RTX A5000, 24 GB)

A 12-24h unattended run on Windows. **Do NOT skip the pre-flight steps.**

```powershell
# 0. Apply Supabase migration 004 (training_runs heartbeat table)
#    Paste migrations/004_training_runs.sql into Supabase SQL Editor and Run.

# 1. Install LLaMA-Factory (one time)
git clone https://github.com/hiyouga/LLaMA-Factory.git LLaMA-Factory-src
cd LLaMA-Factory-src
python -m pip install -e ".[torch,metrics]"
cd ..

# 2. Pre-flight the dataset (catches broken JPEGs, mismatched <image> tags)
python scripts/preflight_dataset.py
# MUST exit 0 — fix preflight_problems.txt errors before continuing.

# 3. Make Windows Update wait until after training
#    Settings -> Windows Update -> Pause for 5 weeks
#    AND (admin shell): NoAutoRebootWithLoggedOnUsers = 1 in WindowsUpdate\AU registry

# 4a. Foreground (good for first run / debugging — blocks terminal):
python scripts/train_qlora.py

# 4b. As a Windows service (best for unattended overnight runs):
choco install nssm                    # one-time
# Run as Administrator:
.\scripts\setup_training_service.ps1
Start-Service QwenTrain               # kick it off
Get-Content outputs\stdout.log -Wait -Tail 50    # tail logs

# Monitor remotely from any device — query Supabase training_runs:
#   SELECT run_id, status, current_step, total_steps, train_loss, eval_loss,
#          gpu_temp_c, vram_used_gb, eta_seconds
#     FROM training_runs ORDER BY started_at DESC LIMIT 1;
```

**Resume after a crash / reboot:**
```powershell
# Find the latest checkpoint
ls outputs\qwen25vl-qlora-gaps-rdd\
# Resume (run_id stays the same so heartbeat updates continue same Supabase row)
python scripts/train_qlora.py --resume outputs\qwen25vl-qlora-gaps-rdd\checkpoint-2400
```

**Expected on A5000 4-bit:** ~12-24 hours total. Adapter saved every 200 steps to
`outputs/qwen25vl-qlora-gaps-rdd/checkpoint-XXXX/`. With `save_total_limit: 3` plus
the best checkpoint, max disk use is ~10 GB.

### Phase 4.5: Adapter Promotion (manual gate)

After training finishes:

```powershell
# 1. Identify the best checkpoint by reading trainer_state.json log_history.
#    (We trained 2500 steps, eval-step lows: 500=0.0603, 1000=0.0485, 1500=0.0478,
#    2000=0.0633, 2500=0.0655. step-1500 was best but pruned by save_total_limit.
#    Closest survivor = checkpoint-1000.)
#    DO NOT use the parent dir outputs/qwen25vl-qlora-gaps-rdd/ — that's the
#    final overfit step.
python scripts/04_post_finetune_eval.py --adapter-path outputs/qwen25vl-qlora-gaps-rdd/checkpoint-1000

# 2. Run the A/B comparison — applies promotion criteria
python scripts/ab_compare_adapters.py
# Exits 0 if criteria met, prints decision + writes eval_results/ab_comparison_table.md

# 3. If promoted: copy adapter to versioned dir, update .env
$ts = Get-Date -Format "yyyyMMdd"
mkdir adapters\v2-rdd-2epochs-$ts
Copy-Item outputs\qwen25vl-qlora-gaps-rdd\checkpoint-1000\* adapters\v2-rdd-2epochs-$ts\ -Recurse
# Drop a metadata.json next to adapter_config.json (records training stats,
# delta vs baseline, base model hash, promotion timestamp) — see existing
# adapters/v2-rdd-2epochs-20260507/metadata.json for the schema.
# Edit .env: ADAPTER_PATH=adapters/v2-rdd-2epochs-YYYYMMDD
# Restart server: it now serves the new adapter on the same /classify endpoints.
```

**Promotion criteria (in `scripts/ab_compare_adapters.py`):**
- Stage 1 accuracy must improve by ≥ 3 percentage points
- Stage 2 macro F1 must improve by ≥ 10 percentage points
- Normal-class precision must NOT regress by more than 5 pp
- All three must hold simultaneously

## Constants & Label Maps

### Stage 1: Binary Detection (GAPs)

```
GAPS_LABEL_MAP = {
    0: "Normal",     # Intact pavement
    1: "Distress",   # Any type of damage
}
```

### Stage 2: Distress Types (RDD)

```
RDD_LABEL_MAP = {
    0: "Longitudinal Crack (D00)",   # Cracks parallel to road direction
    1: "Transverse Crack (D10)",     # Cracks perpendicular to road
    2: "Alligator Crack (D20)",      # Interconnected web pattern
    3: "Pothole (D40)",              # Bowl-shaped holes
    4: "Other Distress",             # Catch-all
}
```

### Extended Distress Taxonomy (in system prompt, for few-shot recognition)

The model is trained to also recognize types BEYOND the RDD labels:
- **Cracking:** Block Crack (D43), Edge Crack, Reflective Crack
- **Surface Deformation:** Rutting, Shoving, Depression
- **Surface Defects:** Raveling, Bleeding, Polishing
- **Patches:** Inlaid Patch (D44), Applied Patch, Utility Cut Patch
- **Joints:** Open Joint (D50), Joint Seal Damage
- **Other:** Weathering/Oxidation, Water Damage

### Severity Heuristic (for training data generation)

| Condition | Severity |
|---|---|
| Has pothole OR 5+ annotations | High |
| 2+ distress types OR 3+ annotations | Medium |
| Everything else | Low |

### `scripts/tests/test_pipeline_robustness.py`

Smoke-tests the operator pipeline against five failure modes. Server must be running with all env vars set, including `ENABLE_TEST_FIXTURES=1`.

| Flag | Type | Default | Purpose |
|---|---|---|---|
| `--only` | list | (all) | Run only named tests: `404`, `corrupt`, `timeout`, `midstop`, `concurrent` |
| `--keep` | flag | False | Don't delete test rows from Supabase on exit |
| `--api-base` | str | `http://localhost:8000` | Override API base URL |

Run:
```bash
python scripts/tests/test_pipeline_robustness.py
python scripts/tests/test_pipeline_robustness.py --only midstop concurrent
```

What each test does:
- **404** — inserts a row with image_url=`https://httpbin.org/status/404`. Verifies retries exhaust and row is marked `failed` with the HTTP error in `error_message`.
- **corrupt** — inserts a row pointing at `test_fixtures/corrupt.jpg` (147 bytes of garbage with a JPEG magic header). Verifies the worker fails fast (non-transient) with PIL's "cannot identify image file" error.
- **timeout** — inserts a row pointing at `https://httpbin.org/delay/120`. Verifies the worker handles malformed/non-image responses gracefully via the failed status.
- **midstop** — inserts a real RDD image, waits for the worker to claim it, hits `/operator/stop`, verifies the row either drains (`classified`/`expert_review`) or releases back to `pending`. Restarts the pipeline at the end.
- **concurrent** — inserts 5 pending rows, calls `claim_pending_assessments` RPC twice in parallel, verifies the returned id sets do NOT overlap (proves `FOR UPDATE SKIP LOCKED` works).

## Training Config Reference

See `configs/qwen25vl_qlora_sft.yaml`. Every key explained:

### Model & Method
| Key | Value | Why |
|---|---|---|
| `model_name_or_path` | `Qwen/Qwen2.5-VL-7B-Instruct` | Best open-source VLM for our use case |
| `template` | `qwen2_5_vl` | Correct tokenization template for Qwen2.5-VL |
| `finetuning_type` | `lora` | Parameter-efficient fine-tuning (trains <1% of params) |
| `lora_rank` | `64` | Higher rank = more capacity, good for classification |
| `lora_alpha` | `128` | 2x rank is standard scaling factor |
| `lora_dropout` | `0.1` | Regularization — prevents overfitting on 50k dataset |
| `lora_target` | `all` | Apply to all linear layers (better than selective) |
| `freeze_vision_tower` | `true` | Vision encoder is already strong, only train language |

### Quantization
| Key | Value | Why |
|---|---|---|
| `quantization_bit` | `4` | QLoRA: model at 4-bit, LoRA at full precision |
| `quantization_method` | `bitsandbytes` | NF4 quantization with double quantization |

### Training
| Key | Value | Why |
|---|---|---|
| `num_train_epochs` | `2` | Research: 50k datasets overfit at 3+ epochs |
| `per_device_train_batch_size` | `4` | Per-GPU micro batch |
| `gradient_accumulation_steps` | `8` | Effective batch = 32 (smoother gradients) |
| `learning_rate` | `1e-4` | Standard for LoRA rank 64 |
| `warmup_ratio` | `0.1` | 10% warmup for stability |
| `lr_scheduler_type` | `cosine` | Smooth decay to near-zero |
| `bf16` | `true` | BFloat16 for Ampere+ GPUs |

### Regularization (prevents overfitting)
| Key | Value | Why |
|---|---|---|
| `weight_decay` | `0.05` | L2 penalty on weights |
| `label_smoothing_factor` | `0.1` | Softens targets, prevents overconfidence |
| `neftune_noise_alpha` | `5.0` | Embedding noise improves generalization |

### Early Stopping
| Key | Value | Why |
|---|---|---|
| `eval_strategy` | `steps` | Evaluate during training |
| `eval_steps` | `500` | Check val loss every 500 steps |
| `load_best_model_at_end` | `true` | Keep best checkpoint, not last |
| `metric_for_best_model` | `eval_loss` | Lowest val loss = best model |

### Performance
| Key | Value | Why |
|---|---|---|
| `flash_attn` | `fa2` | Flash Attention 2: faster training, less memory |

The mobile app inserts a row here for every uploaded photo. The pipeline does NOT modify this table — a Postgres trigger auto-creates a matching `assessments` row.

|---|---|---|

## Row Level Security (RLS) Policies

Two keys exist in Supabase:

| Key | Where it's safe | What it does |
|---|---|---|
| `service_role` (in `.env` as `SUPABASE_SERVICE_KEY`) | Server-side only — never put in browser | Bypasses RLS entirely. Used by `app/worker.py` and the FastAPI server. |
| `anon` (hard-coded in `expert_ui/index.html`) | Safe for browser | Subject to all RLS policies below. |

### `assessments` policies

| Policy | Role | Cmd | Condition | Where it came from |
|---|---|---|---|---|
| `Users view own assessments` | authenticated | SELECT | `user_id = auth.uid()` | `db_schema.sql` (initial) |
| `Users insert own assessments` | authenticated | INSERT | `user_id = auth.uid()` | `db_schema.sql` (initial) |
| `Service role full access assessments` | service_role | ALL | `auth.role() = 'service_role'` | `db_schema.sql` (initial) |
| `Anon read pending review assessments` | anon | SELECT | `needs_expert_review = TRUE` | migration 003 (expert UI) |
| `Anon read reviewed assessments` | anon | SELECT | `expert_reviewed = TRUE` | migration 003 (expert UI) |
| `Anon update pending review assessments` | anon | UPDATE | `needs_expert_review = TRUE` | migration 003 (expert UI) |

### `photos` policies

| Policy | Role | Cmd | Condition | Where it came from |
|---|---|---|---|---|
| `Service role full access photos` | service_role | ALL | `auth.role() = 'service_role'` | migration 002 |
| `Public read photos` | (any) | SELECT | `true` | migration 002 |

### `custom_distress_types` policies

| Policy | Role | Cmd | Condition | Where it came from |
|---|---|---|---|---|
| `Public read distress types` | (any) | SELECT | `true` | `db_schema.sql` (initial) |
| `Service role manage distress types` | service_role | ALL | `auth.role() = 'service_role'` | `db_schema.sql` (initial) |
| `Anon insert custom distress types` | anon | INSERT | (always allowed) | migration 003 (expert UI) |

### `retrain_jobs` and `worker_state` policies

| Policy | Role | Cmd | Condition |
|---|---|---|---|
| `Service role manage retrain jobs` | service_role | ALL | `auth.role() = 'service_role'` |
| `Service role full access worker_state` | service_role | ALL | `auth.role() = 'service_role'` |

**Note on the anon-access tradeoff (migration 003):** the expert UI runs with the public anon key in the browser. To make it work without auth, anon is allowed to SELECT/UPDATE rows where `needs_expert_review = TRUE` and SELECT rows where `expert_reviewed = TRUE`. Anon CANNOT touch any other rows (pending classification, processing, classified-not-flagged, failed, etc.). When you ship to real users, switch to Supabase Auth and re-scope these policies to `TO authenticated` instead of `TO anon`.

## Troubleshooting

### "CUDA out of memory"
- Reduce `max_pixels` in the processor: add `min_pixels=256*28*28, max_pixels=512*28*28` to `AutoProcessor.from_pretrained()`
- Use `QUANTIZATION_BITS=4` (default)
- For RTX 4050 (6-8GB): use `Qwen/Qwen2.5-VL-3B-Instruct` instead of 7B

### "flash-attn build fails"
- Skip it. The code auto-falls back to SDPA (PyTorch native). Flash Attention is optional.
- On Windows, flash-attn often fails to build. Use Linux for training.

### "MUST_UPDATE_TO_ABSOLUTE_PATH"
- Run `python scripts/05_setup_training_config.py` to replace placeholders.

### "No x chunk files found"
- The GAPs dataset isn't in the expected location. Check `GAPs v2/v2/NORMvsDISTRESS_50k_160/train/`.

### "peft: merge produces identical weights"
- This is peft bug #2586. The code already handles this by NOT calling `merge_and_unload()` on quantized models.

### Model generates verbose responses instead of "Normal"/"Distress"
- This is expected for the BASE model (before fine-tuning). The parser handles it.
- After fine-tuning, responses become structured.

### validate_all.py fails
- Run from the project root: `cd Capstone && python scripts/validate_all.py`
- If `expert_ui` test fails, the HTML may have been modified externally.
